# v0.4 产品评审与交付

本版把分类流程改为“选择范围 → 生成建议 → 检查 → 应用／撤销”，同时提供中英设置和可移植导出。现有扩展目录和本机小助手继续使用。

## 六项需求与验收

| 需求 | 本版行为 | 验收依据 |
| --- | --- | --- |
| 全部频道重新分类 | “全部频道（包括已分类）”覆盖全部已收集频道；可追加或替换勾选频道的归属 | 模拟请求包含已分类频道；生成不改状态；替换只影响勾选项；撤销恢复原归属 |
| 中英切换 | 设置页即时保存，已打开的分类面板同步切换 | 未保存模型输入保留；预览保留；刷新后语言保持；用户分类名不翻译 |
| 实时修改进度 | 设置显示验证、授权、保存、完成；分类显示完成数量、批次、等待秒数 | 浏览器观察到真实保存阶段；进度条与返回结果数量一致 |
| 分类复用 | JSON 恢复、CSV 表格、Markdown 频道清单 | 实际下载三种格式；分类归属保留；不含 AI 密钥 |
| UI／UE | 可见字段标签、替换提示、撤销、滚动操作区、折叠说明、深色设置 | 浅色、深色和 390 像素窗口截图；实际操作回归 |
| 淡雅图标 | 鼠尾草绿、雾蓝、浅薰衣草色叠卡与播放符号 | 实际扩展入口、设置页加载；16／32／48／128 像素 PNG |

“全部”以本地已收集列表为准。扩展仍需要用户加载 YouTube 订阅列表，不能证明已经收集完整账号订阅。

## 界面流程审查

证据来自本轮隔离 Chromium 中真实加载的扩展，页面、频道和模型结果均为测试数据。没有检查真实账号或进行用户研究。

1. **进入分类面板：基本清晰，有重复说明。** 旧面板已经提供订阅入口和本地保存提示；有频道后仍显示完整入门说明，挤占操作空间。本版保留页面入口，收起重复说明，加入真实图标。
2. **选择范围并生成：旧入口易混淆。** 旧下拉框缺少可见标签，“全部频道”仍然只能补充分组。本版分别标明分类范围、处理数量和应用方式，明确说明替换对象与收集范围。
3. **检查并应用：可编辑预览是优点，恢复路径不足。** 本版保留低把握默认不勾选，新增撤销与后续编辑冲突检查。长预览使用独立滚动区，主要操作区随面板滚动保持可见。
4. **修改设置：旧版完成结果清楚，保存过程不清楚。** 本版显示当前配置摘要、未保存状态和实际保存阶段。摘要不展示密钥；双语切换保留尚未保存的模型与地址输入。

## 分类在其他地方的用途

- 本扩展：浏览频道、按分类筛选已加载的订阅视频。
- 其他设备／兼容浏览器：导出 JSON，再在同一软件中“合并备份”。原有分类保留，同名分类合并。
- 表格工作流：CSV 中每行是一个频道，包含名称、URL、分类和简介，可在接受 CSV 的软件中筛选、排序或重新整理。
- 笔记工作流：Markdown 提供频道链接和分类名称，可复制或导入支持 Markdown 的笔记工具。

导出不等于同步。外部修改不会自动回写本扩展；CSV 和 Markdown 当前不能在本扩展恢复。没有为 YouTube 账号创建官方分组或播放列表，也没有写入外部应用账号。

## 产品优先级与下一步

本版优先处理可造成分类丢失的问题，再解决操作可理解性，最后增加复用与视觉识别。后续建议按下面顺序评估，尚未实现：

| 优先级 | 建议 | 解决的问题 |
| --- | --- | --- |
| P1 | 预览中按低把握、已编辑、未勾选过滤，并显示分类前后对照 | 大量频道逐条复核成本高 |
| P1 | 保存未应用的任务与预览，刷新后恢复 | 长任务中刷新页面会丢失未应用结果 |
| P1 | 显示频道收集覆盖情况与重复身份待合并项 | 避免把“已收集”误认为完整订阅列表 |
| P2 | 分类规则模板与同义分类合并 | 减少跨批次出现近义分类名称 |
| P2 | 选择具体外部应用后再设计双向同步 | 同步需要冲突规则、账号授权与失败恢复 |

建议先用现有频道验证替换与撤销流程，再根据实际复核习惯决定下一项。没有使用本轮模拟测试推断真实分类准确率、节省时间或用户满意度。
